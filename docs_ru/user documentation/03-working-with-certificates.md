# 03. Работа с сертификатами

Обзор разделов интерфейса и различий между ними.

## Без авторизации

Два раздела доступны всем:

| Раздел | Что даёт |
|---|---|
| **Home → Overview** | Статистика и общая информация об установке |
| **Tools → Certificate Info** | Разбор загруженного сертификата - через проводник или перетаскиванием |

Certificate Info показывает Subject, издателя, серийный номер, сроки, SAN, назначение
ключа, точки проверки отзыва, а также Subject Key Identifier и Authority Key
Identifier - последние удобны при разборе проблем с цепочкой.

## Servers certs

Раздел для сертификатов, которыми сервисы принимают соединения.

- **Add ssh key** - свои SSH-ключи для подключения к серверам, куда будут копироваться
  сертификаты
- **Add servers** - серверы, на которые возможна доставка
- Сертификаты выпускаются с назначением **TLS Web Server Authentication** и
  **TLS Web Client Authentication** - подходят и для приёма соединений, и для взаимной
  аутентификации между узлами кластера
- Домен автоматически добавляется в SAN, даже если поле осталось незаполненным
- При включённом переключателе **Save to server** сертификат копируется на выбранный
  сервер по SSH. Для сервера в статусе `offline` выпуск с этой опцией отклоняется

## Clients certs

Раздел для сертификатов, которыми клиенты подключаются к сервисам.

- **Add entities** - сущности, к которым привязываются сертификаты
- **Add OIDs** - дополнительные пользовательские поля в сертификате
- Сертификаты выпускаются с назначением **TLS Web Client Authentication**

## EST

Автоматическая выдача сертификатов устройствам по протоколу RFC 7030.

| Подраздел | Назначение |
|---|---|
| **Add EST users** | Учётные записи для первичной выдачи: логин, пароль, лимит выдач, срок жизни аккаунта |
| **Add EST certs** | Ручной выпуск сертификата без участия протокола |
| **Revoke EST certs** | Отзыв, откат и удаление |

Устройство получает первый сертификат по логину и паролю, а обновляет его уже
предъявляя выданный сертификат - пароль для этого больше не нужен.

Счётчик выдач ограничивает число сертификатов на одну учётную запись: когда он
исчерпан, запись переводится в состояние `disabled`.

## Переключатель Recreate

Доступен при выпуске серверных и клиентских сертификатов. Если он включён, истёкший
сертификат будет автоматически перевыпущен - локально и, при включённом Save on server,
заново скопирован на сервер.

Действует только для истёкших сертификатов. Действующий сертификат так не обновить.

## Отзыв и откат

При отзыве указывается причина - она попадает в CRL и в OCSP-ответы. Список
перегенерируется сразу, ждать планового обновления не нужно.

Откат возвращает сертификат в оборот: запись исчезает из CRL, а OCSP снова отвечает
`good`.

Отзыв сертификата не затрагивает другие: каждый существует автономно. Повторный выпуск
для того же объекта создаёт новый сертификат, а не заменяет существующий.

## Пересоздание CA

Отзыв Root или Sub CA запускает цепную реакцию:

1. Все сертификаты, подписанные этим CA, отзываются
2. Ранее отозванные и истёкшие удаляются
3. Создаётся новый CA
4. Все действующие сертификаты выпускаются заново под новый CA
5. Сохранённые на серверах - копируются повторно
6. CRL перегенерируется

Операция затрагивает всю установку сразу, поэтому её стоит планировать: до завершения
перевыпуска клиенты, уже получившие старые сертификаты, не пройдут проверку цепочки.

Сертификаты, подписанные внешними CA, в этот процесс не попадают - они не зависят от
вашей иерархии.

## Внешние CA

Раздел **CA → External CA** позволяет загрузить чужую иерархию (сертификаты и ключи) и
подписывать ею сертификаты. При выпуске появляется выбор в поле **Signing CA**.

Особенность: проверка отзыва для таких сертификатов работает через OCSP. В CRL они не
включаются - этот список подписан вашим Sub CA и для чужой иерархии неприменим.

## Выгрузка

Для каждого сертификата доступны три формата:

| Формат | Содержимое |
|---|---|
| **zip** | Сертификат, приватный ключ и цепочка CA |
| **pkcs12** | Контейнер `.p12`, современное шифрование |
| **pkcs12-legacy** | Контейнер `.p12` для macOS и старого ПО |

Пароль контейнера - тот, что указан при выпуске.
